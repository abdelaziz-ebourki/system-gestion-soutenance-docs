\section{Réalisation et développement}
\label{ch4}

\subsection{Introduction}
\label{ch4:intro}

Ce chapitre présente l'implémentation technique du système. Il décrit l'environnement de développement, l'architecture détaillée du code, l'implémentation des différents modules fonctionnels ainsi que les difficultés rencontrées et les solutions apportées.

\subsection{Environnement de développement}
\label{ch4:environnement}

Le développement a été réalisé avec un ensemble d'outils et de configurations rigoureux. Le système d'exploitation utilisé a été Windows 11 ou Linux, couplé à VS Code pour le frontend, enrichi par les extensions nécessaires pour React, Tailwind CSS et ESLint. Le backend a été développé sur IntelliJ IDEA Ultimate, tirant profit des plugins Spring Boot, JPA et Maven. Le versionnement du code source est assuré par Git et GitHub pour la collaboration, tandis que Postman a été utilisé pour tester et documenter les API REST.

\subsection{Implémentation du backend (Spring Boot)}
\label{ch4:backend}

Le backend est structuré selon l'architecture Spring Boot en couches, séparant les contrôleurs exposant les endpoints REST, les services contenant la logique métier et les règles de gestion, ainsi que les repositories assurant l'accès aux données via Spring Data JPA. Les entités représentent les tables de la base de données, tandis que la sécurité est gérée par la configuration Spring Security et les filtres JWT.

\subsection{Implémentation du frontend (React)}
\label{ch4:frontend}

Le frontend, développé avec React et Tailwind CSS, repose sur une architecture modulaire composée de composants réutilisables. La navigation est orchestrée par React Router, la gestion d'état par React Context et les hooks, et les appels HTTP vers le backend par Axios. Enfin, l'interface utilisateur est construite avec Shadcn UI pour assurer une cohérence visuelle et une expérience moderne.

\subsubsection{Module 1 : Authentification et gestion des rôles}

L'authentification repose sur le standard \textbf{JWT (JSON Web Token)} avec une architecture stateless.

\begin{figure}[H]
    \centering
    \pumlsvg[0.9\textwidth]{seq_auth}
    \caption{Diagramme de séquence : Processus d'authentification JWT}
    \label{fig:auth_seq_impl}
\end{figure}

Flux d'authentification :
\begin{enumerate}[label=\textcolor{primary}{\arabic*}.]
    \item L'utilisateur soumet \texttt{email + password}
    \item Backend: \texttt{BCryptPasswordEncoder} valide le hash
    \item \texttt{JwtTokenProvider} génère un token signé (HMAC-SHA256) valide 2 heures
    \item Claims inclus : \texttt{sub=userId}, \texttt{role=ADMIN|COORDINATOR|TEACHER|STUDENT}
    \item Le frontend stocke le token dans \texttt{localStorage}
    \item Chaque requête ultérieure inclut l'en-tête \texttt{Authorization: Bearer <token>}
\end{enumerate}

Sécurité côté backend (\texttt{SecurityConfig.java}) :
\begin{itemize}[label=\textcolor{primary}{\textbullet}]
    \item \textbf{Stateless} : Aucune session côté serveur
    \item \textbf{Role-based access control} :
    \begin{itemize}[label=\scriptsize$\circ$]
        \item \texttt{/api/admin/**} $\rightarrow$ \texttt{ROLE\_ADMIN}
        \item \texttt{/api/coordinator/**} $\rightarrow$ \texttt{ROLE\_COORDINATOR}
        \item \texttt{/api/teacher/**} $\rightarrow$ \texttt{ROLE\_TEACHER}
        \item \texttt{/api/student/**} $\rightarrow$ \texttt{ROLE\_STUDENT}
    \end{itemize}
    \item \textbf{Endpoints publics} : \texttt{/api/login}, \texttt{/api/auth/**}, \texttt{/swagger-ui/**}, \texttt{/h2-console/**}
    \item Custom handlers pour \texttt{401 Unauthorized} et \texttt{403 Access Denied}
\end{itemize}

\subsubsection{1. Génération JWT (Backend)}

\begin{minted}[frame=single, linenos, breaklines, fontsize=\small]{java}
// JwtTokenProvider.java
@Service
public class JwtTokenProvider {

    @Value("${app.jwt-secret:s3cr3t-k3y-f0r-d3f3ns3-m4n4g3m3nt-syst3m-2026}")
    private String jwtSecret;

    @Value("${app.jwt-expiration-ms:7200000}") // 2 hours
    private int jwtExpirationMs;

    public String generateToken(Integer userId, Role role) {
        Date now = new Date();
        Date expiryDate = new Date(now.getTime() + jwtExpirationMs);

        return Jwts.builder()
                .subject(userId.toString())
                .claim("role", role.name())
                .issuedAt(now)
                .expiration(expiryDate)
                .signWith(getSignInKey())
                .compact();
    }

    private SecretKey getSignInKey() {
        byte[] keyBytes = Decoders.BASE64.decode(
            java.util.Base64.getEncoder().encodeToString(jwtSecret.getBytes())
        );
        return Keys.hmacShaKeyFor(keyBytes);
    }
}
\end{minted}

\subsubsection{2. Vérification de conflit : Double réservation enseignant}

\begin{minted}[frame=single, linenos, breaklines, fontsize=\small]{java}
// ConflictDetectionService.java - extrait
@Service
public class ConflictDetectionService {

    public List<ConflictResult> validateSlotAssignment(SlotAssignment slot) {
        List<ConflictResult> conflicts = new ArrayList<>();

        // Récupère le projet et son jury
        Optional<Project> project = projectRepository.findById(slot.getProjectId());
        if (project.isEmpty()) return conflicts;

        // Vérifie chaque membre du jury
        List<JuryMember> members = juryMemberRepository.findByJury_ProjectId(slot.getProjectId());
        
        for (JuryMember member : members) {
            LocalTime slotStart = slot.getTime();
            LocalTime slotEnd = slotStart.plusMinutes(DEFAULT_DURATION);
            
            // Cherche d'autres créneaux pour ce même enseignant à la même date
            List<SlotAssignment> teacherSlots = slotAssignmentRepository
                .findByDateAndJuryMembersContaining(slot.getDate(), member.getTeacher());
            
            for (SlotAssignment existing : teacherSlots) {
                if (existing.getId().equals(slot.getId())) continue;
                
                LocalTime existingStart = existing.getTime();
                LocalTime existingEnd = existingStart.plusMinutes(DEFAULT_DURATION);
                
                // Vérifie chevauchement
                if (timesOverlap(slotStart, slotEnd, existingStart, existingEnd)) {
                    conflicts.add(ConflictResult.builder()
                        .type("teacher_double_booked")
                        .severity(Severity.ERROR)
                        .teacher(member.getTeacher())
                        .conflictingSlot(existing)
                        .message("Enseignant " + member.getTeacher().getUser().getFullName() + 
                                 " déjà affecté à " + existing.getTitle() + 
                                 " (" + existing.getTime() + ")")
                        .build());
                }
            }
        }
        return conflicts;
    }
}
\end{minted}

\subsubsection{3. React Query : Hook personnalisé (Frontend)}

\begin{minted}[frame=single, linenos, breaklines, fontsize=\small]{typescript}
// use-coordinator-queries.ts - extrait
import { useQuery, useMutation, useQueryClient } from '@tanstack/react-query';
import { 
  getProjects, createProject, updateProject, deleteProject,
  getSchedule, saveSchedule, validateSchedule, generateSchedule,
  type CreateProjectRequest, type SlotAssignment 
} from '@/lib/api-coordinator';

export function useProjects() {
  return useQuery({
    queryKey: ['coordinator', 'projects'],
    queryFn: getProjects,
    staleTime: 30_000 // 30s
  });
}

export function useCreateProject() {
  const queryClient = useQueryClient();
  
  return useMutation({
    mutationFn: (data: CreateProjectRequest) => createProject(data),
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ['coordinator', 'projects'] });
      queryClient.invalidateQueries({ queryKey: ['coordinator', 'stats'] });
    }
  });
}

export function useSchedule() {
  return useQuery({
    queryKey: ['coordinator', 'schedule'],
    queryFn: getSchedule
  });
}

export function useGenerateSchedule() {
  const queryClient = useQueryClient();
  
  return useMutation({
    mutationFn: () => generateSchedule(),
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ['coordinator', 'schedule'] });
    }
  });
}
\end{minted}
