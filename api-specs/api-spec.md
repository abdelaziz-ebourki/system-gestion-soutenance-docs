# API Specification — Système de Gestion de Soutenances

> Generated from frontend mock handlers, types, and business logic.
> All endpoints are prefixed with `/api` in the frontend (`fetch("/api" + endpoint)`).

## Authentication

### `POST /login`

Authenticate user by email and password.

**Request body:**
```json
{ "email": "string", "password": "string" }
```

**Success `200`:**
```json
{
  "user": { /* User object (without password) */ },
  "token": "mock-jwt-token-{role}",
  "expiresAt": 1234567890
}
```

**Errors:**
| Status | Condition | Message |
|--------|-----------|---------|
| `401` | Email not found or password wrong | `"Identifiants invalides (E-mail ou mot de passe incorrect)"` |
| `403` | Account not yet verified (`isActive === false`) | `"Veuillez activer votre compte via le lien de vérification envoyé à votre adresse email."` |

---

### `POST /auth/verify-account`

Verify a newly created account. Token is a UUID generated by `crypto.randomUUID()` at user creation, stored on `DbUser.verificationToken`, and deleted after use.

**Request body:**
```json
{ "token": "string", "password": "string" }
```

**Success `200`:**
```json
{ "message": "Account verified successfully" }
```

**Errors:**
| Status | Condition |
|--------|-----------|
| `404` | Token not found (invalid or already used) |

## Admin: Users

### `GET /admin/users`

**Query params:** `?role=student|teacher|coordinator&page=0&limit=10`

**Success `200`:** `PaginatedResponse<User>`
```json
{ "items": [ /* User[] */ ], "total": 10, "pageCount": 1 }
```

### `GET /admin/students`, `GET /admin/teachers`, `GET /admin/coordinators`
Same paginated format as above.

### `GET /admin/users/teachers-list`, `GET /admin/users/students-list`
Same but returns all items at once (no pagination).

### `POST /admin/users`

Create a single user (generic, role specified in body).

**Request body (partial `User` + role-specific fields):**
```json
{
  "lastName": "string",
  "firstName": "string",
  "email": "string",
  "role": "student|teacher|coordinator",
  "cne": "string",        // if student
  "majorId": "string",    // if student
  "levelId": "string",    // if student
  "gradeId": "string",    // if teacher
  "departmentId": "string" // if teacher
}
```

**Success `201`:** `User` object (without password).

**Errors:**
| Status | Condition |
|--------|-----------|
| `400` | Referenced `majorId`, `levelId`, `departmentId`, or `gradeId` not found |

**Side-effects:**
- User created with `password: ""`, `isActive: false`, `verificationToken: crypto.randomUUID()`
- Verification link logged to console: `/verify-account?token={uuid}`
- Role-specific row added to `students`, `teachers`, or `coordinators` table

### `POST /admin/students`, `POST /admin/teachers`, `POST /admin/coordinators`

Same as generic but role-specific. `role` is implicit.

### `POST /admin/users/bulk`

**Request body:**
```json
{
  "users": [ /* array of flat objects with lastName, firstName, email + role-specific fields */ ],
  "role": "student|teacher|coordinator"
}
```

**Validation:** For students, checks that all referenced major/level `name`s exist (looked up by name, not ID). For teachers, checks department/grade names.

**Success `201`:** `User[]`

### `PUT /admin/users/:id`

Update a user. Accepts partial fields.

**Errors:** Same FK validation as create. `404` if user not found.

### `DELETE /admin/users/:id`

**Dependency checks (return `409` with French message):**

| Role | Dependencies checked |
|------|---------------------|
| `teacher` | Department head (`headId`), jury member, supervisor of projects |
| `student` | Linked projects via `tblProjectStudents` |

**Success:** `204 No Content`

**`DefenseSession` schema:**
```json
{
  "id": "string",
  "globalSessionId": "string",
  "name": "string",
  "defenseType": "pfe|memoire|these",
  "status": "draft|active|scheduled|completed|archived",
```

```
draft → active → scheduled → completed → archived
```
Only forward transitions allowed. Invalid transition returns `400`.

| `PUT` | `/coordinator/juries/:id` | Update — partial (same shape as POST) |

**`Jury` schema:**

```json
  "id": "string",

  "projectTitle": "string",
```

```json
  "id": "string",
```

## Coordinator: Grades

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/coordinator/grades` | List all project-grade summaries |

Returns one entry per jury, computing weighted averages from individual teacher evaluations × role coefficients.

**`ProjectGrade` schema:**
```json
{
  "projectId": "string",
  "projectTitle": "string",
  "defenseDate": "string|null",
  "status": "completed|pending|no_evaluations",
  "finalScore": "number|null",
  "evaluationCoefficients": { "Président": 30, "Rapporteur": 35, "Examinateur": 35 },
  "individualScores": [
    { "roleName": "string", "teacherName": "string", "score": "number|null" }
  ]
}
```

**Statuses:**
- `completed` — all evaluations submitted → `finalScore` is the weighted average
- `pending` — some evaluations submitted, some missing
- `no_evaluations` — no evaluations submitted at all

**Grade calculation (server-side):**
```
finalScore = Σ(score × coefficient) / Σ(coefficient)
```
Scores are on a 0–20 scale. Coefficients are percentage integers (0–100). Decision: `≥ 10` → "Admis", `< 10` → "Ajourné".

## Conflict Detection Engine

Located at `src/lib/conflict-engine.ts`. Validates a slot assignment against 8 checks:

| # | Check | Severity | Condition |
|---|-------|----------|-----------|
| 1 | Project already scheduled | `error` | Project ID already exists in schedule |
| 2 | Slot occupied | `error` | Another project occupies the same `date|roomId|time` |
| 3 | Room capacity | `error` | Project student count > room capacity |
| 4 | Date out of session bounds | `error` | Date outside defense session `startDate`–`endDate` |
| 5 | Teacher double-booked | `error` | Jury teacher assigned to another project same day |
| 6 | Supervisor time conflict | `warning` | Supervisor assigned to another project same day |
| 7 | Break interval violation | `warning` | Gap between slots in same room < `breakDuration` |
| 8 | Teacher unavailable | `error` | Jury teacher has declared unavailability for that date/time |

**`ConflictContext` input:**
```json
{
  "schedule": "Record<string, SlotAssignment>",
  "rooms": "Record<string, { id, name, capacity }>",
  "groups": "Record<string, { id, studentIds[] }>",
  "projects": "Record<string, { id, studentIds[], supervisorId }>",
  "teachers": "Record<string, { id, name }>",
  "juries": "Record<string, { id, projectId, teacherIds[] }>",
  "unavailability": "Record<string, { date, slots[], teacherId }[]>",
  "defenseSession?": "{ startDate, endDate, breakDuration }"
}
```

**`ConflictIssue`:**
```json
{
  "type": "room_capacity|teacher_double_booked|supervisor_conflict|break_violation|out_of_bounds|slot_occupied|project_already_scheduled|teacher_unavailable",
  "severity": "error|warning",
  "message": "string",
  "slot": "string",
  "suggestedResolution?": "string"
}
```

## Entity Relationship Summary

```
Department ──┬── Room
              └── Teacher (via departmentId)

User (role: student) ──→ Student (cne, majorId→Major, levelId→Level)
User (role: teacher)  ──→ Teacher (gradeId→Grade, departmentId→Department)
User (role: coordinator) ──→ Coordinator

Session ──→ DefenseSession (globalSessionId)
DefenseSession ──→ JuryRoleTemplate (juryRoleTemplateId)

Project ──┬── ProjectStudent ──→ User (student)
          ├── Jury (templateId → JuryRoleTemplate, members[].teacherId → User teacher)
          ├── Group ──→ GroupMember ──→ User (student)
          └── Defense ──┬── DefenseTeacher ──→ User (teacher)
                        └── Evaluation ──→ User (teacher)
                         
Defense ──→ Room
TeacherUnavailability → User (teacher)
StudentGroup → User (student)
StudentDocument → (linked by student context)
```

## Common Error Patterns

| Status | Usage |
|--------|-------|
| `400` | FK validation failure — French message listing missing entities |
| `404` | Entity not found by ID |
| `409` | Delete blocked — French message listing dependent entities |
| `204` | Successful delete (no body) |
| `201` | Successful create (entity body) |
